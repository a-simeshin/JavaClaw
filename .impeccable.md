# JavaClaw Design Context v3

Enterprise AI-agent platform (Java/Spring Boot 4 + Spring AI 2.0). This document is the source of truth for all UI design decisions. Every builder (`/frontend-design`, `/audit`, `/polish`) MUST consult this before making visual choices.

---

## 1. Users

**Primary:** техлиды и архитекторы. They make decisions, review system state, configure agents/skills/MCP servers, read logs, manage cron jobs.

**Secondary:** AI power-users who experiment with prompts and workspaces.

**Context:** full-screen desktop (≥1280px). They are skeptical, experienced, allergic to marketing fluff.

**Job to be done:** understand what the agent is doing → intervene when needed → configure safely → feel confident the system is under control.

---

## 2. Brand Personality

**3 words:** engineered, deliberate, precise

**Voice & tone:** factual, dense, no marketing copy, no exclamation points. Terse labels.

**Emotional goals:** confidence, spatial depth, a "designed" feel. The interface should feel like good dev-tooling (Linear, Vercel dashboard, Raycast).

---

## 3. Aesthetic Direction

**Strategy:** shadcn/ui technical base (primitives, Tailwind v4, CVA) layered with Gradianto Midnight Blue visual depth (purple-tinted dark palette, layered panels, whisper-thin borders).

**Theme priority:** dark-first flagship (Gradianto Midnight Blue), light-mode fully supported (warm parchment).

---

## 5. Typography

**Display / technical:** JetBrains Mono — логотип, навигация, заголовки секций, timestamps, labels, kv-блоки, таблицы, статус-пиллы. Разработчики узнают этот шрифт мгновенно.

**Body:** Outfit (geometric sans) — user messages, agent body text, input field.

> **Rationale.** Аудитория живёт в JetBrains IDE. JetBrains Mono как display-шрифт — мгновенное узнавание. Serif и italic запрещены для контента.

|--------------------|----------------|--------|---------|----------------|-------------|
| Logo               | JetBrains Mono | 20px   | 700     | -0.03em        | 1           |
| Page title         | JetBrains Mono | 16px   | 700     | -0.02em        | 1.2         |

### 6.2 Responsive

Desktop-only, ≥1280px. < 1024px — not supported, show viewport warning.

|-----------------|-------|------------------------------|

## 7. Motion

Duration 0.15–0.25s, `cubic-bezier(.25,.8,.25,1)`. Fade+slide (translateY 5px) for new messages. `prefers-reduced-motion: reduce` — all transitions ≤ 0.01ms.

## 8. Iconography

`@tabler/icons-react`, stroke-width 1.5, 16–18px in-context. Fallback: custom SVG matching Tabler grammar (24×24 viewBox, stroke 1.5, round cap/join).

## 10. Data-Dense Components

### 10.1 Tables

Four tasks: lookup, comparison, scanning, batch actions. Sticky header. Virtualization > 100 rows. Row hover: `--surface-card` (dark) or `--surface-elevated` (light). Density toggle (36px dense / 44px comfortable).

### 10.2 Log Viewer

Monospace 13px. Left border color = status token + text label. Auto-scroll pinned when user scrolls up.

### 10.3 Truncation

|   Element   |             Strategy             |
|-------------|----------------------------------|
| Agent name  | Ellipsis 24ch, tooltip           |
| Log message | Ellipsis, expand on click        |
| URL/path    | Middle-truncate                  |
| Timestamp   | Relative default, absolute hover |
| JSON        | Collapsed, expand inline         |

### 10.4 UI States

**Loading:** skeleton placeholders mirroring layout, `aria-busy="true"`. **Empty:** icon + heading + action (no illustrations). **Error:** plain language + recovery action + `--error` left border.

## 12. Design Principles

1. **Depth over decoration** — layered surfaces, not shadows.
2. **Calm precision** — dense information, generous whitespace around it. One accent family used surgically.
3. **Engineered restraint** — no emoji, no marketing, no mascots. Labels are terse.
4. **Accessible by default** — WCAG 2.2 AA.
5. **Consistent primitives** — shadcn/ui, Tailwind v4, CVA.
6. **Status is not optional** — every entity has a state, always visible.

## 13. Anti-AI-Slop Rules

### 13.1 Banned Patterns

**Типографика:**
- Нельзя Inter, Roboto, Arial, Open Sans как primary font. AI-tell.
- Нельзя serif. Нельзя italic для контента.
- Нельзя один шрифт на всё. Monospace (JetBrains Mono) + sans (Outfit) — два уровня иерархии обязательны.

**Цвет:**
- Нельзя чистые серые (`#808080`, `#666`). Нейтрали ВСЕГДА тонированные — purple hue для dark, warm hue для light.
- Нельзя cyan-on-dark (`#38BDF8`). Это дефолтная палитра AI.
- Нельзя неоновые/насыщенные акценты на тёмных поверхностях.
- Нельзя придумывать палитру с нуля. **Палитра берётся из реальной IDE-темы** (Gradianto Midnight Blue) или проверенного дизайн-референса (MP113, Profico). Самопридуманные hex-коды — путь к «выглядит как кал».

**Компоновка:**
- Нельзя одинаковый визуальный вес user/agent сообщений. User = голый текст (17px/600). Agent = left-border + кв-блоки + таблицы.
- Нельзя карточки в карточках.
- Нельзя оборачивать каждое сообщение в контейнер/карточку. Сообщения — это текст на странице с тонкой left-border у агента. Как Claude и ChatGPT.
- Нельзя inline styles (`style={{}}`). CSS-классы.
- Нельзя generic spinner > 1 с. Skeleton или streaming.
- Нельзя gradient text.

### 13.2 AI-Slop Test

> Если показать интерфейс человеку и сказать «это сгенерировал AI» — он сразу поверит?

Если да — переделывать.

### 13.3 Что работает

- **Палитра из IDE-темы** — пользователь уже привык к этим цветам, они протестированы на тысячах часов кодинга.
- **JetBrains Mono как display font** — мгновенное узнавание аудиторией.
- **Структурная дифференциация** user/agent через форму, не через цвет.
- **Данные как данные** — kv-блоки, таблицы, code blocks в monospace с собственным фоном.
- **Тёплая light-тема** — parchment/cream, не cold white. Sidebar в той же палитре, не контрастный.

## 14. Lessons Learned (из итераций чат-интерфейса)

Эта секция фиксирует ошибки, которые были допущены при построении UI, чтобы не повторять их.

### 14.1 Палитру нельзя придумывать — её нужно брать

Попытки сгенерировать палитру с нуля (cool-blue, warm espresso, deep indigo) — все выглядели «дёшево и убого». Работающее решение: взять palette из реальной IDE-темы (Gradianto Midnight Blue), которую целевая аудитория уже использует каждый день. Каждый цвет привязан к конкретному ключу в theme.json — нет самопридуманных hex-кодов.

### 14.2 Структура важнее цвета

Одна и та же структура (sidebar + messages + input) выглядела плохо при десяти разных палитрах. Перелом случился когда изменилась **структура**: убрали карточки вокруг сообщений, добавили типографическую дифференциацию user/agent, сделали input как search bar. После этого даже простая палитра заработала.

### 14.3 Accent из той же семьи, что и фон

Orange accent на cold-blue фоне конфликтует — два температурных мира. Фон и accent должны жить в одной цветовой семье:
- Dark (Gradianto): purple surfaces → purple accent (#8769cf, #544c91)
- Light (parchment): warm cream surfaces → warm amber accent (#cc6418)

Попытка смешать MP113 Habanero (#F98513) с midnight-blue фоном давала диссонанс, несмотря на хороший contrast ratio.

### 14.4 IDE-темы > brand-палитры для dev-tool UI

Brand-палитра (MP113: Deadly Depths + Habanero) работает для маркетинговых страниц с большими цветовыми плоскостями. Для UI с мелким текстом, таблицами, kv-блоками нужна палитра, оптимизированная для длительного чтения — это IDE-тема.

### 14.5 Serif и italic — чужие для developer audience

Instrument Serif italic на user messages выглядело «манерно». JetBrains Mono заработало мгновенно — аудитория видит его каждый день. Для dev-tool: monospace > serif, прямой текст > italic.

### 14.6 Sidebar в той же палитре, что и content

Dark sidebar + light content = необоснованный разрыв. Unified palette (sidebar на ступень темнее/светлее content) создаёт ощущение единой среды. Как в JetBrains IDE: Project panel и Editor — разные оттенки одной палитры, не контрастные миры.
